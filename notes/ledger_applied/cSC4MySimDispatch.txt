REASONS:
- UpdateState (0x1006aeb5a): all three state branches (idle 3, travelling 2, no-trip -1) are transcribed, but cISC4PathFinder::FindPath (vslot 0xb8) is unrecovered and goes through IMySimDispatchHost::FindPath; the U-Drive-It route hand-off of the path-found branch is approximated with IMySimDispatchRoute::SetRouteInfo (0x4c0) instead of the original 0x4b8 GetRouteInfo -> 0x4c0 sequence.
- SwitchTravel (0x1006b0b16): the flag dispatch and the walk / new-leg / stuck branches are transcribed, but the 4.5 KB body also interleaves the transit-stop occupant-manager search (spOccupantManager 0x148/0x180 with the +0x38 group from tables 0x100a28730/0x100a28750), the automaton hand-off for a resumed trip and the U-Drive-It branch; those sub-branches are not written and the function falls back to the walk leg for them.
- BasicDispatch (0x1006b1fa2): automaton create/reuse, flag setup, model offset and SetRouteInfo are implemented, but cISC4AutomataManager::CreateAutomaton (vslot 0x78) has eight arguments whose float/register positions the decompiler dropped (the call shows a literal 0 for the group and the position); the seam documents the assumed order.
- CreateAutomaton (0x1006b2c08): the model-key fallback (map key -1), manager selection, the two-AddRef/one-Release reference dance and the 0x1bc42c49 property are implemented, but the same lost 0x78 argument mapping applies, so the key/position handed to the manager are inferred.
- UpdateNeighborLocation (0x1006b06ec): the recovered body is a Ghidra stub that always returns 0; only the neighbour lookup (spSC4 0x118 -> occupant manager 0x58 -> spNeighborsSim 0x60) is visible and the connection -> cell mapping dropped at 0x1006b0740 is missing, so the function calls the host seam and still returns false.
- Thunks: compiler-generated non-virtual thunks; the real methods (QueryInterface/AddRef/Release/Write/Read/DoMessage/GetGZCLSID) are recovered above.
